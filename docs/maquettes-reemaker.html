Point clé : contrairement au tampon « Annexe X Folio n/N » d'Annexio (une ligne), le cartouche est un tableau à cellules, avec orientation et zoom, et un folio par page choisi dans un ordre continu sur plusieurs documents (départ à 46).

Le zoom agit sur la taille du texte (taille de base réglable) ; la largeur suit le texte. Plage prévue : 0,5 à 3.

Mesure

Largeur du texte calculée avec les vraies largeurs Helvetica (déjà utilisées par Annexio) : le cartouche ne déborde jamais de ses cellules.

Colonnes

Colonne de droite = la plus large des cellules de droite ; la ligne 1 occupe toute la largeur ; trait intérieur identique à la bordure.

Position

Coin haut-gauche mémorisé en proportion de la page ; le cartouche reste dans la page (pas de débordement).

Fond

Fond blanc optionnel (déjà présent dans Annexio) pour masquer ce qu'il recouvre.

Règles

  • En mode Auto, le cartouche suit la rotation de la page : il se lit dans le même sens que le texte.

Votre capture montre une page pivotée : le tampon y est placé couché. Cette gestion est donc indispensable, pas optionnelle.

PLANLivraison, tests et questions à valider

Rien n'est codé tant que vous n'avez pas validé ces maquettes.

Étapes de livraison (une version = +0,0.1)

VersionContenu
1.1.18Brique « cartouche » (dessin vectoriel en tableau, 4 orientations, zoom, pages pivotées) + onglet ReeMaker : formulaire, aperçu en direct, foliotage page par page, enregistrement.
1.1.19Page de garde (dans le foliotage et seule).
1.1.20Tampons personnalisés 1 et 2 + réglages ReeMaker (listes, style, modèle des lignes).

Comment c'est construit

  • Bibliothèque (lib.rs) : module cartouche — dessine tableau + texte dans le PDF, avec rotation de page ; module couverture pour la page de garde. Testés sans interface.
  • Interface : nouvel onglet, état « foliotage en cours » (page courante, positions, folios), aperçu qui dessine le même cartouche que le PDF final.
  • Mémorisation : nouveaux champs dans le fichier de réglages existant (anciens réglages conservés).
  • Aucune nouvelle dépendance réseau ; l'application reste hors ligne (hors vérification de mise à jour).

Comment je le vérifierai

  • Tests automatiques : texte des cellules, incrément des folios, pages pivotées 0/90/180/270°, débordement.
  • Captures de l'application lancée (comme pour les versions précédentes) comparées à ces maquettes.
  • Compilation Windows. Non testé sous Windows par moi : l'essai final reste chez vous.

Questions pour vous (réponses courtes suffisent)

1. Nom de l'onglet : « ReeMaker » (comme votre logiciel) ou un autre nom ?
2. Sigles : « Site de … 1 » = numéro de tranche ? Si plusieurs tranches sont cochées : afficher « 1-2 », « 1, 2 », ou un cartouche par tranche ?
3. Le cycle doit-il apparaître dans le cartouche ou seulement sur la page de garde ? Pour quels types d'arrêt est-il actif ?
4. Page de garde : avez-vous un modèle à reproduire ? Quels champs doit-elle contenir ?
5. Tampons personnalisés 1 et 2 : à quoi servent-ils chez vous ?
6. Validation : clic droit et Entrée vous conviennent-ils pour « valider et page suivante » ?
7. Le folio est-il par page (46, 47, 48…) même si certaines pages sont ignorées (« Passer ») ?
Une dernière précision : ces maquettes reprennent les fonctions de ReeMaker++ avec l'habillage d'Annexio ; elles ne copient ni son apparence ni ses textes.
